Дата: 2026-11-25. Сервер запускался локально (`PORT=3100 node server.js`), тесты — curl-запросами к API. После тестов база очищена: проект едет на хостинг с пустой `data/`, первый зарегистрировавшийся станет владельцем.

## Примечание среды

В песочнице сборки `better-sqlite3` не собрался из исходников (node-gyp упёрся в права на распаковку заголовков Node), поэтому локально был поставлен официальный prebuild-бинарник v12.4.1 с GitHub Releases — функционально это тот же пакет. На обычном хостинге `npm install` ставит его штатно.

## Повторная проверка после перевода на прод-стек (2026-11-25)

Стек заменён: **Postgres вместо SQLite** (`pg`, пул из `DATABASE_URL`), **Cloudinary вместо `data/uploads`** (multer memoryStorage → официальный SDK), приложение вынесено в `app.js` под **Vercel serverless** (`api/index.js` + `vercel.json`).

Как проверяли: временный настоящий PostgreSQL 19.0 поднят локально из бинарников npm-пакета `embedded-postgres` (initdb/postgres запущены напрямую, база `eventide` создана через `pg`), приложение запущено как `DATABASE_URL=postgres://…@127.0.0.1:5544/eventide CLOUDINARY_STUB=1 PORT=3200 node server.js`. Smoke-тест — 26 проверок curl/fetch-запросами, **все пройдены ✅**, включая все пункты из таблицы выше (регистрация владельца и второго пользователя, дубликат `MISHA` → 409, пост/лайк/комментарий, сообщение и `read=true` после открытия, канал+пост+подписка+channel-feed, поиск по кириллице «вечер»/«ГОСТЬ», админка 403/галочка, живой Deezer-поиск и чарт).

Дополнительно проверено:

| Проверка | Результат |
|---|---|
| Схема в Postgres | Создано 16 таблиц; колонки `*_public_id` есть у users/posts/reels/channel_posts/user_tracks и заполняются при загрузках |
| Загрузка трека | WAV «Test Artist - Test Song.wav» распознан из имени файла; в базе `file` = Cloudinary URL и `file_public_id` заполнен |
| Загрузка рилса и аватарки | Приняты; в ответах API — Cloudinary URL |
| Vercel entry | `api/index.js` как HTTP-handler: `/` → 200, `/api/music/chart` без входа → 401 (как положено) |
| Локальный запуск | `node server.js` с `DATABASE_URL` на временный Postgres работает (этот же запуск и тестировался) |

⚠️ **Про Cloudinary честно:** реального аккаунта Cloudinary при проверке не было, поэтому загрузки шли через встроенный стаб (`CLOUDINARY_STUB=1` в `media.js`): он проверяет весь путь «multer memory → uploadMedia → secure_url+public_id в базу → URL в ответах API», но сам файл в облако не отправлял. Реальную загрузку в Cloudinary нужно проверить один раз после подключения аккаунта (задать настоящий `CLOUDINARY_URL` без стаба и загрузить аватарку). Тип ресурсов выбран по документации SDK: картинки — `image`, видео и аудио — `video` (Cloudinary принимает аудио как video-ресурсы).
